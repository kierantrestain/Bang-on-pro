## 2. Bounded quality feedback loop

Plan → execute → **assess → correct → verify** → human approval → approved preference learning. Implemented in `department/quality_loop.py` and `jobs.py`. A correction is kept only if **all** of these hold:

1. The agent's objective score improves by at least 0.02.
2. **No new critical defect** appears. Defects are matched by code, severity and master-clock position (±0.5 s), so swapping one error for another is rejected even when the error count is unchanged.
3. An **independent QC guard** shows no increase in any critical finding. The guard is the built-in checks plus every registered check, so an assessor cannot game its own score.

There are at most 2 attempts per agent and 6 per job. Attempts run on a fresh copy of the pre-run state in an isolated directory and reuse cached analysis. A failed attempt keeps the original output. **Every attempt, including rejected and failed ones, counts toward processing time and the job budget.** An attempt that would exceed the budget is skipped.

## 4. Measurements: V1.2.1 vs V1.2.2

### Agent-level ground truth (unit/synthetic)

| Measure | V1.2.1 | V1.2.2 |
|---|---|---|
| Editorial scenarios (podcast question/punchline/laugh, news dead air, gameshow suspense/applause, crosstalk/interjection, false starts): editor fixes needed | 21 | **0** |
| Meaningful pauses kept | 0 % | **100 %** |
| Sync with drift, dropout and a late start (120 s): worst error | **13.3 s** (`cam_c`, outside ±30 s) and 1.5 s (`cam_a`, dropout) | **≤ 1 frame** |
| Drift | not measured | recovered within 2.4 ppm |
| Extra time for the sync refinement | n/a | +0.4 s |

The editorial scenarios use words supplied directly, as if from Whisper, so they show what the agents do with a real transcript.

### End-to-end ground truth on identical inputs (`bench_v122_compare.py`, synthetic)

Setup: 4 genres × 2 generated multicamera scenarios, same briefs, mode `full_production_draft`, the same V1.2.1 profile files for both versions, $0 budget, no Whisper (VAD path). Linux x86_64, 4 vCPU. Results are in `docs/evidence/v1.2.2/v121_vs_v122_benchmark.json`.

| Mean per job (8 jobs per version) | V1.2.1 | V1.2.2 |
|---|---|---|
| **Corrective fixes an editor would need (total)** | 13 | **10** |
| of which speech on the wrong camera / pause removed / shot under minimum | 8 / 4 / 1 | 4 / 4 / 2 |
| Speech on the correct camera | 85.7 % | 88.0 % |
| Speech retained | 99.7 % | 99.7 % |
| Review items to read | 5.25 | 8.0 (was 14.0 before review consolidation) |
| Machine processing | 3.3 s | 5.5 s (quality loop 0.016 s) |
| Peak RSS: Python / largest child | 227 / 209 MB | 232 / 227 MB |
| Re-edit, editorial stage (cache hit) | 0.002 s | 0.006 s |
| External cost | $0 | $0 |

Defects the benchmark exposed, and their fixes:

- **Review workload tripled.** The same root cause was reported by several agents. Review items are now consolidated per root cause onto the agent that fixes it.
- **Crosstalk was hidden in a close-up** in all 8 jobs for both versions. A short crosstalk wide now borrows time from a neighbouring shot instead of being absorbed.

### Human editing time (60–85 % target)

**NOT MEASURED.** It needs paired editor sessions on real footage. The instrument is now in the app (timing sessions, human time separate from machine time, corrective-work counts); run it using [INTERNAL_TESTING_PROGRAMME.md](INTERNAL_TESTING_PROGRAMME.md).

## 5. Known limitations (explicit)

- **Without a Whisper model**, the editorial gains are limited. Pauses inside a speaker's turn are still shortened below a natural beat: 4 of 8 benchmark jobs, the same as V1.2.1. Captions are withheld. Install Whisper small in the Model Manager for the beta.
- **Review workload** is still about 50 % higher than V1.2.1 on synthetic footage (8.0 vs 5.25 items). The extra items are distinct findings, such as colour limits on solid-colour test cameras and low-confidence segments. Tune them with real footage.
- **Processing time** is about +65 % on short programmes, mostly multi-window sync and sampled visual analysis. It is still seconds per job, but long-form scaling needs measuring on real recordings.
- **VFX:** no temporal mask propagation yet (static matte per camera; refine in Roto Studio). **Distribution:** 9:16 versions use a centre crop; subject-aware reframing is not implemented.
- **Gameshow and sports discussion** profiles now target −23 LUFS (EBU R128). Set −16/−14 for online-only delivery.
- **Specialists were stopped** at usage limits before finishing. Their work was integrated by the lead and covered by the tests above, but the editorial and media test scenarios were designed by those specialists. The end-to-end benchmark above is the independent check.
- **No physical-Mac testing, signing or notarisation** (EXT-002): the DMG is ad-hoc signed and verified on a virtualised Apple Silicon runner. No real licensed multicamera footage (EXT-005), no human editor sessions (EXT-003), huggingface.co blocked in the dev container (EXT-004; neural ASR is verified in macOS CI).
