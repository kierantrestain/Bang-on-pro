# Bang On Pro V1.4: the production agents do the editing (internal pre-release)

**Branch:** `claude/great-fermi-lq9n81`, built on V1.3 (`c2d5c3e`; that commit is the rollback point). V1.3 was never published as a release; V1.2.2 is still the latest pre-release.

**Development:** done by one lead engineering agent; no development agents were spawned. Reference repositories were inspected only for patterns, and no code was copied ([working notes](V1.4_WORKING_NOTES.md)). No new runtime dependencies, models or services. Python's `mcp` SDK was used only as a test client, and that test is skipped when the SDK is not installed.

**Evidence:** footage is **synthetic** (a generated 3-camera podcast) on Linux x86_64 with 4 vCPU. No real productions were run and no editors took part.

## What changed for an editor

The editor gives a creative instruction in Claude Code or Codex, or in the Revise field. The 14 agents then inspect the footage and edit the draft with Bang On Pro's native operations. They check the result on the actual draft, correct what Quality Control finds, and report what they changed. Each change is an ordinary, editable and undoable edit in the Kdenlive project. Connection steps are in [AGENT_CONNECTION_GUIDE.md](AGENT_CONNECTION_GUIDE.md).

## Delivered, in implementation order

| Milestone | What works | Where |
|---|---|---|
| 1. Reasoning connected to the command infrastructure | **Stdio MCP server**: handshake with version negotiation, 23 discoverable tools, each with a title and read-only/destructive hints. Unknown or invalid arguments get `-32602` naming the accepted ones; bad lines get `-32700` and the server keeps serving. Tool failures come back as structured `isError` results (code, message, hint, retryable). Long calls send progress and stop on `notifications/cancelled`. **Session recovery**: all state is in the job folder, so a restarted server resumes at the same revision. Claude Code connects through `claude mcp add`, Codex through `~/.codex/config.toml`. The running app's existing `TimelineCommandServer` is reached through `bop_live`: status, the live timeline including manual changes, and proposals the editor approves per operation | `bangonpro/ai_engine/mcp/` |
| 2. Inspection, visual inspection, native editing | **Draft replay** now applies move, trim, split, delete, audio levels and keyframes, effect parameters, keyframes, dissolves (Kdenlive same-track luma mix), fades, and caption edits. V2 now carries B-roll and still images (`qimage`), not only titles. **Agent edit layer**: every edit is attributed and revision-checked, replayed after the department's own batches, and **verified in the written `.kdenlive` file**. An edit the file doesn't show is undone and reported. **Visual**: contact sheets of on-screen source frames or rendered draft frames, sparse, cached by source identity, time and revision, with agents' notes kept. Also EBU R128 loudness of the rendered range, and checked range previews | `project_builder.py`, `department/edit_layer.py`, `mcp/workspace.py`, `mcp/vision.py` |
| 3. The 14 agents | Same identities and engines. Each now has an editor's brief, **enforced** operation, track and effect permissions, and measurable `done_when` checks. Examples: the Colourist cannot delete clips, Quality Control cannot edit the cut, and the Executive only delegates. A camera switch carries that camera's grade with it. The Learning Agent hands approved series preferences to each task and records finished tasks as corrections | `department/agent_roles.py` |
| 4. Bounded collaboration and visual correction | **`bop_task`** covers understand, inspect, plan, execute, evaluate, correct and verify. It returns a compact context pack (about 2.6 KB here), not a conversation history. Tracks are leased by range, so two agents never change the same range, and findings are shared. Completion checks run on the actual draft. **Draft QC** looks for wrong camera, flash shots, picture gaps, A/V sync, graphics over the wrong speaker or too short, inconsistent colour per camera, level jumps, and captions. It also checks the rendered output for duration, unexpected black, whether the right camera is on screen, and loudness. High-confidence defects are corrected by the owning agent within a budget of 3, **re-checked independently**, and undone if they persist or cause a regression. A planner that gets a check wrong sees exactly what failed, and where QC moved things, and gets one more round. A check it drops is reported as superseded, never hidden. **In-app**: when the rules don't understand a Revise instruction, the Executive asks the editor's own **authorised** CLI (`claude -p` / `codex exec`) for a plan | `department/draft_qc.py`, `mcp/execution.py`, `mcp/reasoning.py` |
| UI | The Agent Control Centre's existing header now shows the connected client, the agent working and its activity, plus the agent-edit count. Unresolved task issues go into the existing Review list under the owning agent. No new panel | `AgentControlCentre.{h,cpp}` |

## Evidence

### 1. Real authenticated AI client (live)

Claude Code CLI 2.1.332 ran in headless mode, signed in with the account's own credentials (no API key, no credential access). It was connected to the MCP server over stdio, with only `mcp__bangonpro` tools allowed and a limit of 30 turns. The record is in [docs/evidence/v1.4/live_claude_code_run.json](evidence/v1.4/live_claude_code_run.json).

- **Instruction (not a predefined command):** *"Make the guest's longest answer feel more dynamic: cut to the host listening once in the middle of it, add the city B-roll near its end with a short fade, and put a Live from the studio title over the opening wide shot."*
- **Result:** 14 turns, 23.6 s, 12 tool calls reached the server. Usage was reported as $0.19 (about 2.8 k output tokens; 508 k cached input tokens read).
- **Edits:**
  - The Multicamera Director switched to `cam_host` for 13.5–15.5 s as a reaction, and the camera's grade came with it.
  - Graphics placed `broll_city.mp4` on V2 at 17.24–19.44 s with 0.4 s fades. It started after the guest's lower third, without being told.
  - Graphics added the title at 0–2 s.
- **Independently verified on the draft:** the camera is guest at 12 s, host at 14.5 s and guest at 16 s. V2 is as described. QC found no defects, and the project file matches the edit.
- **What went wrong:** the client first wrote its completion checks with the wrong key. The task failed those checks, and the client noticed and retried. **Fixed in this release:** checks are now schema-validated up front, and a retried instruction supersedes the earlier task, so the editor doesn't see stale issues.

## Not done or limited (explicit)

- **Synthetic footage only, and human editing time not measured.** The generated footage has tones, not speech, so there are no ASR words. Captions in the tests use supplied text, and editorial judgement on real conversations is untested.
- **One live authenticated run** (Claude Code). **Codex was not run**: its configuration and headless call are implemented and their files tested, but the CLI isn't installed here. The app-driven path (Revise field falling back to an authorised CLI) was exercised with the scripted planner only.
- **The live app path was tested against a simulated socket server, not the real C++ application.** Live proposals are staged for the editor's approval; compound tools such as camera switch and range removal work on the department draft, not on the open timeline.
- **Visual judgement is evidence-based, not semantic.** Camera choice, graphics placement and colour consistency are checked from the transcript speakers, the speaker-camera map and effect parameters. Rendered frames are compared with the expected source frame. No new vision model was added; when a reasoning client looks at a contact sheet, its observations are its own. Framing problems in 16:9 shots are not detected automatically.
- **Edits stop at the edit layer's model:** tracks V1, V2, A1 and A2; one dissolve lane on V1; no speed changes in the draft (the native engine has them live). Markers do not move when a range is removed, and the OTIO export omits the dissolve lane.
- **Vertical clips** are new projects planned from a range. Editing an existing vertical project with the tools is not implemented.
- **Previews render at project resolution** with a low bitrate, because melt's consumer scaling crashes MLT 7.22 on these projects. On a headless Linux machine MLT's Qt module needs a display (`xvfb-run`).
- **Not tested on a physical Mac**, and the build is not notarised.
