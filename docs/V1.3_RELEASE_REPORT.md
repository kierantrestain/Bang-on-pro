# Bang On Pro V1.3: autonomous YouTube editing department (internal pre-release)

**Branches:** built on V1.2.2 (`130d842`) in the branch `claude/bang-on-pro-v1.3`. V1.2.1 stays the stable rollback release and V1.2.2 stays a pre-release.

**Development:** done by the lead alone; no specialist agents were spawned, to save usage. No new dependencies, models, services or repositories were added. Everything runs offline on the existing native Kdenlive/MLT/FFmpeg/Qt stack.

**Evidence:** all evidence below is **synthetic** (generated multicamera footage with labelled ground truth), on Linux x86_64 with 4 vCPU. There were no real productions and no editors, and **human editing time was not measured**.

## Delivered

| Area | What works now | Where |
|---|---|---|
| Creative director | Plain-language revisions become validated plans: learnable overlays plus the first agent to rerun. Scope can be the whole project, a named range ("the opening", "from 1:20 to 3:00") or the timeline selection. **Locks**, earlier revised ranges and everything outside the range are kept verbatim. Exact **undo**. Unclear or unselected requests are explained and change nothing. Revisions are recorded for series learning | `department/revisions.py`, `ProductionJob.revise / lock_range / undo_revision`, CLI `revise`, `lock`, `undo-revision` |
| Production panel | Revise field, *Selection only* (timeline zone), Revise and Undo in the review area. Explanations appear in the status line. Unslop roles unchanged | `AgentControlCentre`, `BangOnProIntegration` |
| Shared project index | Timestamped events built from existing analysis: speech and turns, moments, topics, highlight and vertical-clip opportunities, protected pauses, camera availability, subject evidence, visual changes, clipping, assets. Every entry names its evidence, and missing evidence is listed | `department/project_index.py` → `draft/project_index.json` |
| Pause preservation without words | A pause under 2 s inside one speaker's turn is a **thinking beat**, kept at a per-format length | `editorial_pacing.py` (`beat_pause_sec`) |
| Camera direction | A close-up the profile doesn't name (e.g. a news guest) is diarised as its own speaker. Crosstalk, exchanges and topic changes use a **real wide**. The news desk still opens | `transcribe_diarise.py`, `rough_cut_multicam.py` |
| Vertical clips | **Subject-aware 9:16 reframing** replaces the centre crop. The speaker's close-up is used instead of a wide. A stable subject gets one held crop, a moving one gets smoothed, speed-limited keyframes. With no evidence the crop is centred and reported. Each clip is an **editable native 1080×1920 project** (`qtblend` Transform keyframes). A 360×640 proxy is rendered and the **rendered file is checked**: size, duration, audio, black frames, subject in frame | `department/reframe.py`, Distribution |
| Review workload | Findings consolidated by root cause onto the agent that fixes it. Merged findings keep their details. The cut-rate warning fires only above 15 % over the reference | `jobs._consolidate_review_items` |
| YouTube delivery | All six profiles target −14 LUFS integrated, −1 dBTP. Overrides and approved series preferences still apply | `show_profiles/*.json` |

### Workflow tests on real drafts (`test_v13_creative_director.py`, 14 tests)

- A range revision changes only its range and does not rerun ingest, sync, editorial or the director.
- A lock survives a whole-project revision: the same camera and kept time every 0.1 s.
- Undo restores the draft exactly.
- Unclear or unselected requests change nothing.
- "Create three vertical clips" produces 1080×1920 projects with `qtblend` and rendered, checked proxies.
- The project index is evidence-labelled.
- Source media stay unchanged throughout.

## Not done or limited (explicit)

- **Human editing-time savings: not measured.** That needs paired editor sessions ([INTERNAL_TESTING_PROGRAMME.md](INTERNAL_TESTING_PROGRAMME.md)). **No real footage** was available, so all results above are synthetic.
- **Review workload** is 6.4 items per job including setup notices, still above the 5.25 target. Findings were merged, never hidden.
- **Revision interpretation is rule-based.** It covers the instruction families in the configuration guide; anything else is reported as not understood. No language model is used. An optional configured provider could be added later behind the existing consent and budget gates.
- **Revisions keep earlier work** through range splicing in the shot planner. Edits made by hand in the Kdenlive timeline after promotion are not read back; promote and lock instead.
- **Vertical framing** uses the sampled skin/motion subject boxes, about one sample per second. Without subject evidence (as in the solid-colour test footage) the crop is centred and flagged. MediaPipe was not adopted because the existing analysis met the tests; real footage may justify it. Branded caption templates for vertical clips are not implemented, and captions still need Whisper.
- **Gameshow score graphics, sports statistics graphics and news headline imagery** from supplied assets are not automated in this release. The existing title and lower-third templates and B-roll placement ops are unchanged. Reference-style learning beyond the existing series preferences is not implemented.
- **Not tested on a physical Mac.** The release is not notarised; the DMG is verified on GitHub's virtual Apple Silicon runner.
