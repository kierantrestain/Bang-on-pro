## Reference patterns adopted (no code copied)
- Editroom (MIT): stdio bridge answers `initialize/ping/tools/list` locally, forwards real calls to the running
  app; isolated draft per agent run; tool failures as `isError` results; protocol versions
  2025-06-18/2025-03-26/2024-11-05; `readOnlyHint`; per-call activity line in the UI; observation notes so the
  agent does not look again; connect via `claude mcp add` and `[mcp_servers.x]` in `~/.codex/config.toml`;
  dependency-ordered draft replay (edits touching same clip / same track stretch conflict).
- AutoCut (MIT/Apache): reasoning in the client, media processing local; inspect → run → render frame → look →
  undo loop; strict args (`-32602` naming accepted args); `-32700` on bad lines and keep serving; long jobs with
  `notifications/progress` and `notifications/cancelled`; advisory locks that fail naming the holder.
- REA (MIT): not run (all Bang On Pro native code is in-repo; direct inspection is cheaper). Adopted contract
  guidance: `limit/offset` + `partial` flag on large listings, flat schemas, evidence labels on results.

## Design decisions
- MCP server: stdlib JSON-RPC over stdio (no new dependency; the `mcp` SDK is used only as a dev-side test client
  when installed). Backends: **draft** (department job draft, headless) and **live** (running app socket).
- Reasoning: the connected client (Claude Code / Codex) is the shared intelligence. The app can also invoke an
  installed, already-authenticated CLI headlessly (`claude -p`, `codex exec`) for instructions the rule interpreter
  does not understand. No API keys, no bundled models, no credential access.
- Agents stay 14 entries in one department; each gets a brief, op permissions and completion checks. Edits through
  MCP are attributed to an agent and checked against its permissions, locks, leases and the revision.
